# Changelog

## [0.5.0](https://github.com/impulseframework/impulse/compare/v0.4.0...v0.5.0) (2026-11-18)


### ⚠ BREAKING CHANGES

* session.NewAuth takes who holds the Super Administrator role as its third argument, and an Auth with super administrators needs mail. A role file may not define the role's name. identity.WithAdministratorRoles takes the tenant roles alone. A person holding a global role is no longer exempt from a tenant's sign-in settings. An application regenerates its auth package and its identity tree, and its migrate command seeds the first administrator holding the role.
* every auth's permission store gains the group tables and their indexes from the store's DDL(). A hand-written access.Store implements the group methods, and a hand-written identity.Store implements GroupStore. access.UserManager gains RoleHolders. UserRoles and RoleUsers include roles held through groups, and a role a group holds is not deleted. The starter role files give a place's groups to whoever manages its people; an application's own role file grants nothing over groups until it says so.
* the permission store's UserRoles, GroupMembers and GroupRoles tables gain the nullable columns StartsAt and EndsAt. access.Store's three insert methods take a period, and a hand-written identity.Store implements PeriodStore. The auth package sets SetSignedInHook(identityClient.SignedIn(...)). A role file grants startsAt and endsAt on the role lists to show the period.
* the directories table gains two unique indexes and is keyed by a generated id; its method and connection are output only, and personal accounts are no directory. A custom sessionstorage.AuthStore implements LinkConfirmedIdentity, and a DirectorySeatedHook is also called for an account that already exists.
* a tenant that relied on listing a directory to keep other sign-ins out turns directory only on. The tenant record's directory-only field is output only and is changed by two generated methods, which role files grant Execute on. The session's tenant list carries entries marked closed, which an application that reads the list itself skips; its role file grants cannotEnter. An application regenerates and rebuilds its browser app.
* signin.Policy.Then asks the next rule after a hold. signin.UserRoleManager, resource.SessionUserChecker, access.Controller, access.UserManager and access.UserResourceChecker gain methods, and resource.DirectoryPeople gains a field. A test double that embeds a nil controller answers TenantAdministratorRoles(). The method that turns directory only on, its dry run and its warning refuse a caller with no password.
* sessionstorage.AuthStore gains SetFirstUserPassword, and the mail links table's kind check takes the new kind. The generated router gains two handlers where the auth has passwords.
* a caller who gives roles for the whole application is refused, with 403 and a sentence that says who can, giving or taking a directory-only tenant's administrator roles and changing how one of its administrators signs in.
* a guess spends its attempt before it is judged, a right one included, and a code whose attempts are spent is not reported as standing. For a custom session store, SignInAttempts gains Counted.
* sign-ins with the right password made at once for one name are refused past the limit until one of them finishes, and every password check writes the sign-in attempts table. A custom session store's RecordSignInFailure must count and set Counted in one transaction: a store that leaves Counted false refuses every password check and every mailed code or link.
* a person's own change of password was not held to the minimum; it is now.
* the standard account rules, Config.Accounts, session.OpenSignUp(), the generator's OpenSignUp() and InvitedUsers() and the --accounts flag are removed. An application adds the auth's sign-in methods table, passes session.WithSignInMethodsTableName, calls Auth.SetSignUpSeated(identityClient.SignedUp()), and grants the new list and methods in its role file. A directory member with no account and no invitation is refused until the method is opened. A custom signin.Method gives the identities of its audience.
* nobody creates a tenant through the tenant record's create: a create operation on it is refused, and the generator refuses the creation argument of the tenant annotation. The generated identity client of the auth a tenant is made through takes the generated maker of the tenant record. The mail links table gains the NewTenant column.
* a sign-in that was linked on the name alone is refused. An application that creates accounts ahead for a directory's people invites them, or declares the registration's names its own (SeededUsers).
* a client that sent another value, or sent a header to a route that ignored it, had the call run for real; it is now answered 400 with the header's name.
* for a custom session store, RemoveUserPassword, RemoveProvenUserPassword and UnlinkIdentity take the links that count. signin.Method gains AdmitsConnection, identity.Store.Identities returns links with method and connection, and identity.SessionAPI gains SignsInThrough. The generated API description no longer carries identity[].signIns; role files grant the new lists.
* the pending sign-ins table gains PasswordProof. For an application with its own store: UserStore.SetUserPasswordHash is UpgradeUserPasswordHash, AuthStore.SetUserPassword is ReplaceUserPassword, AuthStore gains ChangeUserPassword and RemoveProvenUserPassword, sessionstorage.SignInRules gains Proven, and LinkConfirmedIdentity takes the proof.
* a stored secret field's type changes to resource.Secret, PatchSet.Resolve takes the keys, and an application needs APP_SECRET_KEY_1. resource.SecretKeysFromEnv refuses the declared name set with no numbered version. `impulse check` gains `secret-holders`, and its `env-template` fails a template that holds a key (`--fix` writes the lines that make one for the checkout).
* the live store's subscription documents keep the tenants as the array domains, and the Firestore index file changes with it: an application takes the new entry into its schema/firestore/firestore.indexes.json. live.SubscriptionRecord.Renew returns the refusals beside the error, which a hand-written record implements. A live subscription over a set of tenants is refused for a resource not declared @listAcrossTenants.
* maintenance.Serve takes the brands, so every application's main changes one line.
* the Preauth store's type is sessionstorage.Preauth[Tx].
* an Entra sign-in's tenant and object id are Identity.Connection and Identity.Subject. An Entra registration gives the authority and the tenants apart, in Config.Authority and Config.Tenants.
* app.LegacyAuth and Generator.LegacyAuths are gone.
* the generator refuses a tenant record whose key is not an impulse.UUID its own create path generates. A tenant is created by an add on the collection with no key in the path and answered with the id; the create-your-tenant route takes the record's fields without the key and answers {"id"}, and its generated TypeScript request loses the key. The domain in every tenant-scoped URL, role and session tenant list is the id's text. The last-administrator refusal reads "of this tenant", in the application's word for a tenant, and no longer carries the domain. The opened invitation and the standing invitation answer tenantId and tenantName in place of tenant
* the permission store's user is the account's id. identity.Manager.AssignRole and RemoveRole take the id, the generated whole-application role methods take userId, and a role is given only to a user that exists. A seed writes its roles under an id it derives and creates the user under that id last. resource.UserPermissions.User() is the account's id, so a column compared with subject holds the id. A session that views as a person names them by account id. session.Auth.SetDirectoryAdmission takes the reader and the hook, identity.RolesFollowRename is removed, and the impersonation table gains the ActorUserId column. A column that holds an account's id ends in UserId: the role table's User column and index (access.Tables.UserRolesByUserID), the impersonation table's PrincipalUser and the mailed links table's InvitedBy are renamed, with the Go and JSON fields that carry them (a membership row's userId, InvitedByUserID and invitedByUserId, principalUserId); likewise every column that holds an id ends in Id: the role tables' Domain is DomainId, the mailed links' Tenant is TenantId and the tokens' Family is FamilyId, with their Go and JSON fields (domainId, tenantId, familyId). A change event's source reads "username (account id), session id"
* an auth's users, pending sign-ins and mail links tables hold a Name column, which the session library reads and writes: its own schema gains it in the SessionNames migration, and the tables impulse new and impulse add auth write carry it. sessionstorage.AuthStore gains SetUserName and ClaimUserName
* an auth's users table holds LookScheme and LookPalette columns, which the session library reads and writes: its own schema gains them in the SessionLooks migration, and the tables impulse new and impulse add auth write carry them. sessionstorage.AuthStore gains SetUserLook
